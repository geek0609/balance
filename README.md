# Balance

Balance is an open-source accounting and business-management application written in Rust. Its long-term goal is to cover the complete range of workflows needed by businesses to move their existing books, inventory and operations into Balance.

**Status: early prototype.** Features listed as available are partial and have not all been verified. Do not use the application for production accounting, statutory filing or irreplaceable records yet. The planned list is a goal, not a claim that the functionality or regulatory compliance already exists.

## Run the prototype

Download and run the Windows x64 setup executable from [Releases](https://github.com/geek0609/balance/releases). It installs for the current Windows user and adds Balance to the Start menu. To build from source on Windows, install a Rust toolchain and run `cargo run`.

Installed copies check for updates hourly while Balance runs. Use **Updates** to change that preference or check manually. When a new version is available, save your work and select **Install update**. Balance verifies the downloaded installer, closes for installation and opens again when setup completes. Install and uninstall leave the accounting database in its separate local application-data directory.

The feature list below describes the source on `main`. Each release page describes the packaged build.

Balance stores a SQLite database in the user's local application-data directory. Create a company, create ledgers in account groups, and enter balanced vouchers. The application is licensed under [Apache-2.0](LICENSE).

To open an existing database at a different absolute path, run `cargo run -- --database "C:\path\to\balance.db"`. The selected path is shown in the application header. The optional path must already exist; the default database is used when the option is omitted.

## Available in the prototype

These capabilities are implemented at a basic level; their coverage, usability and correctness still need comprehensive verification.

- **Companies and accounts:** create and select companies; save company address, contact and registration details, plus informational financial-year and books-start dates, with previous company details retained; create hierarchical account groups and ledgers; rename ledgers or move them to a group in the same accounting category, with earlier names and groups retained; save ledger mailing, address, contact and registration details; maintain optional party credit-day defaults and informational credit limits with prior values retained; enter and revise non-zero opening balances against an automatically maintained opening-difference account, or clear one with a dated counter-entry and reason. Credit-day defaults can be explicitly applied to invoices; limits are not enforced. Reports use current ledger names and groups. Financial year and books start dates are informational. A separate company cutoff locks transaction dates on or before the selected day. Setting, changing or removing the cutoff requires a reason and records the change in company history.
- **Opening receivables and payables:** enter the amounts still outstanding at the opening date, retaining the original bill references, dates and optional due dates. Opening bills post against the opening difference account, can be settled by receipts, payments or advances, and appear in as-of ageing from the original bill date. Sales and purchase registers exclude opening bills. A ledger can use a single aggregate opening balance or itemized opening bills with a separate signed on-account amount. The on-account amount and active opening bills share an opening date. The party summary and CSV show the amount separately from named bills and ageing. A dated clearing entry can offset an opening bill after active allocations are released or reversed. The XML importer accepts ledger opening bills with original dates and optional calendar due dates or whole-day credit periods and records the signed difference between the named amounts and the declared ledger balance on account, including for a zero net opening balance. A receipt or payment in the same import can settle a matching opening bill. Named opening advances on the opposite side of the ledger retain the original reference and date. They post at cutover against the opening difference account and can fund later invoices without another cash movement.
- **Period closing:** the company cutoff blocks new vouchers and stock movements dated in the locked period, including invoices, settlements, opening balances, adjustments, transfers, stock counts and imported entries. Existing voucher edits cannot move entries into or out of the locked period. Later counter-entries and settlements can still refer to earlier vouchers under the rules for those workflows. Ledger and inventory masters, company details and bank reconciliation are outside the transaction lock. Any user of the local prototype can change the cutoff.
- **Accounting entries:** create multi-line balanced vouchers; label them as journal, payment, receipt, transfer, sales, purchase, credit note or debit note; record dates, references and narration; browse and edit ordinary vouchers; retain prior voucher versions; reverse an ordinary voucher with a separate dated journal entry and reason. Mark individual voucher lines as party postings. The marks appear in voucher history and carry into reversals. The original and its reversal then cannot be edited. Voucher labels alone do not produce stock or tax effects; linked invoice, settlement and opening-balance entries use their own workflows.
- **Monthly journals:** save a balanced journal draft as a named monthly schedule. The draft date anchors the first occurrence. Short months use their last day, and longer months return to the original day. Review each occurrence before posting it, or skip it with a reason. Posting uses the original fixed debits, credits and party marks, and respects period locks. The schedule records journal and reversal references and skipped dates. Close a schedule with a reason to stop future occurrences. Use a dated reversal to correct a posted journal. Other frequencies and automatic scheduling are planned.
- **Foreign currencies:** set a company base currency, define foreign currency precision and record dated exchange rates with history. Preview a foreign journal, receipt, payment or transfer in both currencies. Each line converts to base hundredths and the voucher must balance in both currencies. Use a separate income or expense ledger for any rounding difference. The saved voucher retains the original foreign amounts and selected rate. An ordinary voucher reversal preserves those amounts at the original rate. The foreign voucher register shows both currencies. Invoices, settlement exchange differences and revaluation are planned.
- **Accounting reports:** a searchable day book with date and voucher-type filters; ledger activity with opening, running and closing balances; a sales and purchase invoice register filtered by date, type, party or search; date-filtered trial balance with debit, credit and difference totals, account-group trial balance, profit and loss, and balance-sheet summaries. Group totals include descendant groups and use current ledger classifications. Export the filtered day book, ledger activity, invoice register, trial balances, outstanding invoices and party outstanding summaries to new CSV files. The invoice register shows original totals and includes settlements and reversals from all saved dates. Outstanding reports support an as-of date.
- **Printable ledger statements:** export a selected ledger and date range as HTML with company and account details, opening and closing balances, and dated voucher references, debits, credits and running balances.
- **Cost centres:** create company-specific centres and subcentres. Split a saved income or expense posting across centres, with any remainder left unallocated. Changes require a reason and retain the saved splits in history. Reverse ordinary vouchers or invoices to carry their allocations into the counter-entry. Review or export income, expenses and net amounts for a date range, with direct figures, totals including subcentres, unallocated amounts and the company total. Reports use current allocations. Period locks protect allocation changes. Clear a voucher’s allocations before editing its postings. Opening entries and balance sheet postings remain outside the allocation workflow.
- **Budgets:** save named income and expense budgets for a date range and keep previous versions. Choose the whole company or a cost centre, with an option to include subcentres. Compare ledger targets against actual postings or allocated amounts for the same period. View unbudgeted activity, income, expenses, net and favourable variances. The budget report exports to CSV and uses current actuals, even when reviewing an earlier budget version.
- **Cash flow:** mark cash and bank ledgers and classify counterpart ledgers as operating, investing or financing. Report opening and closing cash, inflows and outflows by class, and vouchers behind each amount. Use a voucher classification when its counterpart entries do not identify a clear cash purpose. The report flags mixed and unclassified movements, separates net-zero cash entries, and exports to CSV. Classifications have change history and use current settings even for a historical date range. This report does not change the ledgers.
- **Bank clearance:** mark individual asset-ledger postings with a clearance date on or after the voucher date, review the book, cleared and uncleared totals as of a date, and retain a history of changes. Import a restricted CSV statement and manually match one statement entry to one posting with the same amount; matching uses the statement date as the clearance date and records match changes. A unique eligible posting can be suggested, but must be reviewed and matched manually. Enter a statement opening balance to calculate a statement balance from imported entries and compare it with the books. A match or clearance must be removed before its voucher can be edited; past reports use current clearance dates and opening balances.
- **Stock:** create simple units with up to three decimal places, hierarchical stock groups, items with descriptions, nested locations and item batches with optional manufacture and expiry dates; edit item names, groups and descriptions with previous versions retained; maintain append-only effective-dated base-unit price lists and explicitly fill blank invoice prices for the invoice date; set per-item reorder levels and fixed suggested quantities with prior settings retained; view company-wide low-stock warnings; record quantity-only adjustments and transfers; allocate invoice items to locations and optional batches; view balances and dated movement history across all locations or for one location, plus batch quantities and expiry status for a selected date. Choose direct quantities for one location or include its descendants in the total and CSV. Immediate transfers within the selected branch cancel in its total. The batch view and movement register use the same location scope. The register lists immediate transfers across that boundary and staged dispatches and arrivals affecting the selected locations. Low-stock warnings use current rules, ignore pending orders and do not create purchase orders. The invoice stores the price used but not a link to the list. Existing unbatched movements stay unbatched. Item base units cannot be changed. Quantities can go negative, and adjustments and transfers do not create accounting entries.
- **Standard costing:** set an effective-dated standard cost per base unit with a recorded reason and history. Use the latest rate for a date to value company-wide stock on hand. Report item sales after discounts against the standard rate on the original invoice date, with reversed sales offset at the same rate on the note date. Both reports export to CSV and separate unknown costs from known figures. New rates in locked periods are blocked. Reports use the currently saved rates, exclude tax and adjustments from item-sales margin, and do not book inventory value or cost of sales into the ledgers.
- **Actual-cost valuation:** value stock across all company locations using net purchase item amounts and recorded acquisition costs for positive quantity adjustments, including opening quantities and count gains. Choose weighted average to release a proportion of the combined value, or FIFO to use the oldest remaining receipt first. Both methods use the same acquisition costs. On a single date, the report processes positive adjustments, purchases and restored sales before sales and other issues, with source ID order within each group. Invoices fully reversed on their original date have no net effect. Later sales reversals restore original issue costs on the note date. Purchase reversals issue stock using the selected method. Missing acquisition costs and insufficient stock leave the affected item’s value unavailable and identify the first issue. Acquisition cost changes retain their history and respect period locks. Both methods also show item sales, cost of sales and margin by invoice line for a selected period. Reports separate costed sales from lines that cannot be valued and export to CSV. Same-day sales and their full reversals are omitted from the actual margin report. Reports exclude taxes, freight and other non-item charges and make no ledger postings.
- **Physical stock counts:** record quantities for selected items and batches at one location and date. Preview book quantities and discrepancies, then post the count and any quantity adjustments as one transaction. The app asks for a new preview if a book quantity changes. Count history retains book quantities, observations and linked adjustments, including items whose counts matched. The book quantities include movements already saved through the count date. Later backdated entries can change reported balances without altering the count record. Counts are limited to the lines entered, and adjustments do not post accounting entries or value the stock.
- **Manufacturing:** save named bills of materials for a finished item and keep prior versions. Scale components to a planned output quantity and post their consumption and the finished units in one transaction. Select one location and optional batch for each component and for the output. Posting checks available component quantities on the run date. Review the exact bill version and stock movements in production history. Enter the finished stock’s total acquisition cost for valuation or add it later. Automatic production costing, multiple outputs, job work and production reversals are planned. Production runs post quantities without creating accounting entries.
- **Quotations:** save sales and purchase quotations with a party, dated prices and quantities, an optional expected delivery date and an optional validity date. Convert an open quotation to one order using the quoted items and prices and a selected order reference and date. The order date must fall within the quotation validity period. The quotation retains its order link and conversion time. Close a quotation with a reason when it will not proceed. Export a printable HTML record with quoted quantities, unit prices, subtotal, validity and notes. Printed names and currency come from the current master records. Revise an open quotation by saving a linked replacement with a new reference and a reason. The original remains available in the register. The replacement can be converted to an order. Direct invoicing is planned.
- **Sales and purchase orders:** record orders for stock items with a party, reference, order date, expected date and agreed unit prices. Filter the order register by type, status, reference or party. Prepare an invoice for remaining quantities and adjust the draft for a partial fulfilment. The direct invoice, its voucher and stock movements, and the order link save together. An order can be fulfilled across multiple direct invoices, deliveries or receipts. Close an entire order with a recorded reason, or pre-close part or all of a pending item line. Line closures and reopenings retain their date, quantity and reason. They update the pending order schedule, stock projections and quantities available to fulfil. Printable orders show pre-closed quantities alongside fulfilment and agreed prices. The stock availability report uses all saved dates and excludes closed orders. The pending order schedule lists current unfulfilled lines by expected date, with links to order details and CSV export. Filter by order type and an inclusive expected date. Clear the date filter to include undated orders. The register includes all linked invoices regardless of date, and invoice prices can differ from the agreed order prices.
- **Order amendments:** change the reference, expected date, notes, quantities and unit prices, and add or remove unused lines on sales and purchase orders. The original order type, party and date are retained. The amendment keeps prior terms, line items and a reason in the order history. Quantities must cover fulfilment, line closures and active reservations. Review the amended terms in the register, pending schedule and printed order. Existing invoices and delivery or receipt notes retain their posted terms.
- **Invoices and settlement:** create basic sales and purchase invoices with items, quantities, prices, fixed or percentage item discounts, optional per-item accounting ledgers, multiple location or batch allocations per item, an optional due date or credit period in days, one or more manually entered tax amounts using separate ledgers, and manually entered service, charge or deduction lines; invoices without stock items require a positive service or charge line in a compatible account. Create the related voucher and any stock movements atomically; review invoices; prepare a new draft from an existing invoice with a new date and reference; export a basic printable HTML invoice record to a new file; edit invoices without settlement history with prior versions retained; allocate a partial receipt or payment across one or more invoices of the same party and type; apply settlement discounts to one or more income or expense ledgers while recording net cash and the full amount applied to bills; record named advances and an amount on account in the same receipt or payment; reverse the entire voucher, including its bill allocations, discounts, and on-account amounts, with a separate voucher and reason; view outstanding invoices, party summaries and ageing buckets from the invoice or due date as of a chosen date. Save the transaction as an invoice or a sales or purchase voucher. Save an optional bill reference alongside the document number. It defaults to the invoice number and can be used to find the bill in the sales and purchase register and outstanding reports. Split a document into multiple named bills with individual amounts and due dates or credit days. Allocate receipts and payments to specific bills while retaining one document and one settlement voucher. The outstanding report shows each open bill and the receipt history shows its allocation. Copying retains prices, tax, stock allocations and split amounts for review. Give each copied bill a new reference. Percentage discounts apply to the rounded gross line amount. Past reports and exported documents use current invoice and party details.
- **Tax rate profiles:** save named sale or purchase profiles with several tax ledgers, effective dates and version history. Apply the profile in an invoice to the full amount before tax or to an explicitly entered taxable amount. The app calculates each component separately and rounds it to two decimal places. The saved invoice and its revisions retain the selected version and taxable amount. Rates apply to the same base without compounding. Profiles use the rates and base the user selects and do not determine statutory treatment or prepare returns.
- **Invoice tax register:** filter recorded tax components by document date, sale or purchase and ledger. Full reversals and tax reductions from partial notes appear on their own dates in the original sale or purchase category. Reversing a partial note restores its tax amounts on the reversal date. The register and CSV show separate sales and purchase tax totals by ledger. It covers invoice tax components only and excludes ordinary vouchers, unclassified adjustments and filing calculations.
- **Payroll:** create employee records with a code, department, title, optional employment dates and a payable ledger. Configure pay heads for earnings, deductions and employer contributions. Enter amounts for an employee and period to post the payroll accrual and its balanced journal together. Filter the payroll register by posting date or employee, review pay head details and export totals to CSV. Record full or partial salary payments against accruals and reverse individual payments with a dated counter-voucher. The register and CSV show paid and outstanding amounts through the selected cutoff. Payroll amounts are entered manually. Reverse an accrual after reversing any active salary payments. A replacement can use the same employee and period with a new reference. The register uses reversal dates to distinguish current from historical balances and excludes reversed accruals from the active totals. Export a printable HTML pay statement with the pay head breakdown and payment and reversal status. Attendance and statutory deductions are planned.
- **On-account advances:** record advance receipts from customers and advance payments to suppliers against a cash or bank ledger. Browse the advance register and reverse a recorded advance with a dated counter-voucher and reason. Original and reversing vouchers stay linked to the advance. Apply part or all of an advance to named bills of the same party and type, including individual bills in a split schedule. Release an entire allocation with a date and reason. Each bill and its allocation appear separately in the outstanding report and advance history. Applications and releases update invoice balances and advance availability without posting cash again. The advance register and outstanding reports support an as-of date. Applied advances and settled bill amounts appear separately in invoice reports. Reverse only after active allocations have been released. Applying or releasing advances requires an open period.
- **Delivery and receipt notes:** post dated stock issues or receipts with an item, location and optional batch for each line. Use a standalone note or prepare one for some or all of an order’s unfulfilled items. The order shows fulfilled and invoiced quantities separately. Export a printable stock note with locations, batches and quantities. Bill some or all of a note through one or several invoices with adjustable prices, charges and tax. The note tracks billed and unbilled quantities per line. An invoice reversal makes its quantities available to bill again. Stock stays on the note date and the invoice posts to the ledgers on its own date. Receipt prices set acquisition costs, and the invoice price leaves those receipt costs as recorded. A delivery’s issue cost is shared across its invoices by billed quantity, with the allocation retained for historical reversals. Reverse all active invoices before reversing the stock note. Period locks apply to the date of each posting.
- **Replenishment planning:** review items whose projected balance has reached the reorder level. The projection uses company-wide stock and open sales and purchase quantities across all saved dates. Each suggestion uses the smallest whole number of configured reorder lots that takes the projection above the reorder level. Export the suggestions to CSV or add selected items to an editable purchase order draft. Enter the supplier and prices before saving. Sales orders, purchase orders and quotations can fill blank item prices from a selected price list using the draft date.
- **Negative stock control:** a company can require nonnegative closing quantities for every item, location and batch from a chosen date. Balance checks the opening history and subsequent daily balances, so backdated postings and purchase edits cannot create a later shortage. XML imports check the final balances before committing the batch. Existing companies start with negative stock allowed. Changes to the policy record a reason and retain their history.
- **Stock ageing:** choose an as-of date and three age cutoffs to see remaining company-wide FIFO quantities in four age bands. Select an item to see its receipt dates and quantities. Customer returns and restored issues age from the date they re-enter stock, and internal transfers retain their ages. Missing acquisition costs leave quantity ageing available. The report flags items whose stock history cannot support FIFO ageing. Export the summary, per-band FIFO values where available, and receipt detail as CSV.
- **Stock in transit:** dispatch an item and optional batch between locations, then record partial receipts or returns to the source. Each movement carries its own date, reference and reason. Dispatches require stock at the source and protect sales reservations. Location balances and registers show dated issues and arrivals. Company-wide stock and valuation include units in transit, while the order availability report excludes those units from unreserved stock. The transfer register and CSV support an inclusive as-of date, with an option to include completed dispatches.
- **Sales order stock reservations:** set aside pending quantities by warehouse location and batch and release them in full or in part. Balance checks physical stock today and at the end of each day with a saved future movement. Preview batch allocations for a selected item, location and batch, with an optional quantity limit and expected date cutoff. The preview prioritizes the earliest expected date, then order date, with undated orders last. Applying the preview rechecks the proposed reservations and saves them together. Individual and batch reservations can expire at the end of a chosen local date. Expired holds release their remaining quantities automatically and retain their history. Reservation checks protect the stock through the expiry date when evaluating future movements. A linked delivery or direct invoice consumes matching holds, and the draft uses the held quantities and locations. Billing a delivery keeps the stock movement on the delivery date. A return or reversal can reopen quantity for fulfilment, and you can reserve it again. Closing an entire order releases its remaining holds. Review manual releases and fulfilment in the reservation history, and compare reserved and unreserved quantities in the stock availability report and CSV.
- **Combined stock-note invoices:** prepare one invoice from delivery or receipt notes of the same party and type, including notes against different orders. Choose the quantities to bill from each source line. Posting creates one invoice and leaves stock movements on the original note dates. The invoice lists its source notes, and each order, return and cost report retains the corresponding source quantities. Reversing the invoice makes the quantities on each note available to bill again.
- **Unbilled stock returns:** return part or all of the unbilled quantities on a delivery or receipt. Record the date, reference and reason, and export a printable return. The return moves stock at its original location and batch, updates the quantity available for billing and reopens the returned quantity on a linked order. A dated reversal restores the original fulfilment and billing availability when stock and order quantities allow. Customer returns restore a proportional share of the delivery issue cost. Supplier returns issue stock at the selected valuation method, and their reversals restore that issue cost. The workflow posts stock movements before billing.
- **Receipt cost reconciliation:** compare recorded receipt costs with supplier invoices per item, location and batch. See received, invoiced, returned and unbilled quantities, the recorded cost of the billed quantity, the net amount billed and the difference. Use an optional as-of date and export the report to CSV. Amounts exclude tax, service lines and other charges. The report uses current recorded receipt costs and date-filters movements and invoices. An invoice posted against a receipt does not revise its acquisition cost.
- **Partial credit and debit notes:** reduce the unpaid portion of a sales or purchase invoice using its original ledger and tax components. Each note records a date, reference, reason and balanced voucher. Invoice and ageing reports show the reduction alongside settlements and advances. Reverse an individual note with a dated counter-voucher to restore the bill balance. Export a printable note with the linked invoice, reduction by ledger, tax details and reversal status. Invoice editing is locked after a note is posted. These notes adjust financial balances and leave stock quantities as posted. An imported financial note can apply to several invoices or individual split bills for the same party, including opening bills. The original voucher carries its ledger postings and all bill allocations. Its reversal in Vouchers restores the affected balances from the counter-voucher date. A financial note can carry unused amounts as named credits, including on the same voucher as reductions of open bills. Outstanding shows available credit on the selected date and the application history. Apply or release credit on a later bill and record cash or bank refunds from this screen. Customer refunds are payments and supplier refunds are receipts. A dated refund reversal restores the credit balance.
- **Invoiced stock returns:** select quantities from the allocations on a sales or purchase invoice, including invoices billed from a stock note. The app derives the credit from the original net item prices after discounts and accepts explicit reductions of recorded tax components. The credit or debit note and stock movements post together against the unpaid balance. Return histories retain location, batch, net item credit and the original bill. Order fulfilment, receipt reconciliation, tax, stock valuation and sales margins reflect the return. A dated note reversal restores the bill and reverses the stock movement when quantities allow. Credits beyond the unpaid amount are available for refund. XML import supports sales and purchase stock returns whose item amounts match their original allocations. The note may reduce open bills on the original invoice, carry one or more named credits for later use, or do both. A return with no open-bill allocation must give the original invoice reference, with its date if needed to identify it. The stock history stays linked to that invoice after the credit is applied or refunded. Release active applications and reverse refunds before reversing the return voucher.
- **Refunds against invoice notes:** a credit first reduces the unpaid part of the original bill. Excess credit is available for a refund, including returns on fully paid invoices. Record one or more customer refund payments or supplier refund receipts against the note using a cash or bank ledger. Outstanding shows unpaid refunds by note as of the selected date, with a CSV export. Refund reversals restore the balance on their own dates. Apply part or all of the available credit to another outstanding bill of the same party and type. Applying credit changes both balances without creating a cash voucher. On split schedules, enter the note amount to apply to each bill when posting a credit note, debit note or stock return. Apply any available credit to an individual bill and release that allocation by date when needed. The note retains an allocation history, and a dated release restores the original availability. Reverse refunds and release applied credit before reversing the note.
- **Full invoice reversals:** post a dated credit note for a sale or debit note for a purchase. The reversal offsets the original accounting postings. For an invoice that moved stock directly, it offsets quantities at their original locations and batches. A separate delivery or receipt note keeps its recorded movement until it is reversed. The app retains the invoice and note, marks the invoice as reversed and closes its outstanding amount from the note date. Reversing a direct order invoice restores its unfulfilled quantities unless that order was closed. If a stock note moved the goods, reversing the stock note restores those quantities. Replacement invoices cannot predate an existing reversal on the order. Reverse any active settlements and partial notes and release advance allocations before reversing the invoice. Replacement stock allocations and statutory note documents are planned.
- **Data and continuity:** preview and atomically import a restricted subset of XML from one file or separate master and transaction exports, including supported account groups, ledgers, contact fields, opening balances, voucher lines, record identifiers including voucher keys, simple units, stock groups, locations with parent links, items, opening stock quantities and supported acquisition costs, narrowly supported item and non-stock invoices, invoice settlements with advances and discounts, financial notes with open-bill allocations or named credits, refunds against those credits, and stock returns tied to original invoices, including returns that leave credit. Both files share a 50 MiB limit and one preview. Cross-file references are resolved before applying the batch. Ordinary accounting vouchers retain party marks on their posting lines. Bill allocations require a supported invoice, settlement or financial note workflow. Existing voucher keys block duplicate imports. Export dependent masters only once to avoid duplicate records. Detected unsupported records and fields block the entire import. Create a SQLite snapshot of all companies or restore a backup to a new file, with database integrity and reference checks and schema upgrades on the restored copy.
- **Interface:** Windows desktop app with a grouped sidebar, company switcher, flat blue-and-gold light and dark themes, and a dashboard for posted balances, outstanding invoices, low stock and recent vouchers. Open Go To with `Ctrl+K` to find a screen or action. Use `F4`–`F9` to open common transaction forms and `Ctrl+Enter` to save an ordinary voucher.

### Current limits

- XML import needs verification against representative exports. Invoices and billed sales and purchase vouchers accept new bill references and applications of named advances or credits that add up to the full party amount. Balance keeps each reference and its calendar due date or whole-day credit period and matches imported receipts and payments to the named bill. Item invoices need one accounting allocation per item and matching quantities and amounts. Voucher stock allocations can appear under a trade ledger posting. Their amounts must add up to that posting, and the original ledger postings are retained. Where a voucher stock line has no item rate or discount, the amount divided by quantity must produce an exact rate in hundredths. Stock vouchers without a bill are outside this import workflow. Non-stock invoices require a positive posting to a compatible income, expense or asset account. Separate percentage or fixed item discount fields are accepted when the calculated net amount matches; combined discounts and fixed discounts across multiple stock allocations are unsupported. Multiple location or batch allocations are accepted only when each allocation's discounted amount matches its quantity and price and their rounded amounts sum to the item amount. Additional ledger postings are retained as unclassified service, charge or deduction lines, with no tax treatment inferred. Simple receipts or payments may allocate against available invoices for one party, using one cash or bank asset ledger and matching totals. Income or expense discounts can reduce the recorded cash movement by up to the amount settled on bills, with a positive cash amount required; a repeated due date or whole-day credit period must match the referenced bill. Relative terms on opening bills use the original bill date. Financial credit and debit notes can apply to open bills, carry named credits for later invoices, or do both. The bill allocations and named credits must add up to the party posting. Cash settlements and notes that reduce open bills are applied in date order. Named credits retain their due date or credit period and can fund later invoices in the same import or a separate import without posting cash. A refund can use several named credits and can share one receipt or payment with settlements and advances for the same party. A reference that matches both a bill and a refund credit blocks the import. Reversing the cash voucher restores all its linked balances. An imported receipt or payment can contain several named advance and on-account allocations, either by themselves or alongside bill settlements. Balance retains the original Advance, New Ref or On Account classification and any reference. A named advance may carry a calendar due date or whole-day credit period. An application that repeats the terms must agree with the advance. On-account allocations use no credit terms, and each named advance on a voucher has a distinct reference. The importer can apply a named advance to one or more sales or purchase transactions, fully or partially, on the original invoice dates. The advance must already exist or appear in the same import with a compatible party, direction, date and remaining amount. Balance retains the original reference on the advance and gives each funded portion its own local bill reference, leaving the original unpaid bill references and amounts available for later receipts or payments. Advance applications post no additional cash movements. Opening quantities may be allocated to locations and batches with manufacture dates. Unallocated quantities use the default location. Positive quantities can carry an opening value or a base-unit rate with up to five decimal places. The importer preserves explicit totals that agree with the rate’s precision. A negative value spelling requires a matching positive rate. Batch costs must sum to the item total when the item has a value or rate. The importer assigns a remaining value only when exactly one positive allocation lacks its own cost. Zero-only cost fields leave the cost unspecified. Supported values become acquisition costs for inventory reports and do not create ledger entries. Location names must be unique within the company. Import resolves parent locations before their children and rejects missing parents, cycles and parent conflicts with existing locations. Other payment terms, tax details, expiry dates, invoice batch dates and applications of on-account amounts are unsupported. Orders, order links, physical stock counts, returns with changed item prices, imported reversal records, other inventory transactions, unsupported opening value formats, statutory tax information and many account and transaction fields are also unsupported. A clean preview does not establish that an entire business dataset has been migrated correctly.
- Cost-of-goods ledger postings, jurisdiction-specific tax calculation rules, tax filing and statutory compliance are not implemented. Weighted average and FIFO reports require a complete cost and quantity history for each item valued. Invoice taxes can split across ledgers, with details retained in revisions and printable records. Tax amounts may be entered manually or calculated using a user-selected profile; invoices with settlement or advance allocation history cannot yet be edited, including after reversal or release. A reversal applies to every allocation on its settlement voucher; individual allocations cannot yet be reversed independently. The invoice list includes future-dated settlements, settlement reversals and invoice reversals; use the outstanding report for an as-of view. New settlements cannot be dated before an existing reversal on the same invoice. A new or revised opening balance cannot predate the latest clearing for that ledger.
- Backup, restore, invoice document export and statement import need runtime verification; a failed backup, restore or document export may leave an incomplete destination file. The invoice document is a basic record for review and printing, not a statutory tax layout; it does not show payment status, and company and party details are taken from their current profiles. Restoring creates a separate database and does not replace the one currently in use. Automatic bank matching, many bank statement formats, multi-user access, permissions, comprehensive audit controls, advanced payroll and manufacturing and many specialized reports are not implemented.
- Schema 78 adds a reversal safeguard for combined receipts and payments. Schema 79 retains the original classification and credit terms on imported advances. Schema 80 records opening amounts on account alongside named opening bills. Schema 81 preserves named opening advances. Schema 82 stores each advance separately while keeping one voucher and one reversal. Schema 83 stores discounts on settlement vouchers. Schema 84 stores bill allocations on imported financial notes. Schema 85 preserves imported voucher keys. Schema 86 preserves named note credits, applications and releases. Schema 87 links cash refunds to named credits. Schema 88 links stock returns directly to their vouchers and preserves earlier return history. Earlier builds require a database snapshot from a compatible version.
- This is not a finished or verified migration tool. Keep original records and independently reconcile all data and reports before relying on any future migration.
- The opening-difference ledger name is reserved for the automatically maintained control account. Imports containing another ledger with that name require resolution before they can proceed.

For the restricted bank statement import, prepare a UTF-8 CSV with columns `id,date,description,amount` in that order. IDs must be stable and unique within the selected ledger, dates use `YYYY-MM-DD`, deposits are positive, withdrawals are negative, and amounts have at most two decimal places. The statement opening balance is entered separately; calculated balances depend on the imported entries being complete and are not independently verified. Files are limited to 10 MiB and 10,000 entries.

Report CSV exports include the company and selected date filters. Day-book, invoice-register, trial-balance, outstanding and company-wide stock files contain a `context` row even when no entries match; ledger files contain opening and closing rows. Group trial-balance parent totals include their descendants, so parent and child totals must not be added together. The stock quantity export uses current reorder settings even for a historical quantity date and excludes pending orders and valuation. The stock valuation exports show standard cost, weighted average or FIFO values separately. Debit and credit columns are positive; ledger balances use debit-positive, credit-negative signs. Text that could be interpreted as a spreadsheet formula is prefixed with an apostrophe, which changes those exported text values. Exported reports and spreadsheet handling still need runtime verification.

An open-ended report or stock quantity view includes all saved entries, including entries dated in the future. Supply an end or as-of date when a cutoff is needed.

## Planned feature coverage

The roadmap covers the breadth required for a mature, full-featured accounting and business-management system. Individual items may require substantial design, implementation and verification; the list will be expanded as remaining workflows and edge cases are identified.

### Company and financial setup

- Company profiles, addresses, contact details, financial years, books start dates and configurable accounting periods.
- Multiple companies, company groups, consolidation, inter-company transactions, branch management and separate registrations.
- Company-specific features, numbering, currency, units, defaults, document series and accounting preferences.
- Financial-year transitions, opening a new period, splitting or archiving historical company data and carrying forward balances with reconciliation.
- Opening balances for accounts, inventory, bills and other masters; reconciliation of opening differences; year-end closing, rollover and period locks.

### Chart of accounts and accounting

- Complete account-group hierarchy, custom groups and subgroups, aliases, ledger classifications, multiple addresses and richer account master details.
- Cash, bank, customer, supplier, income, expense, asset, liability and capital accounts; account histories, statements and drill-down.
- Journal, payment, receipt, transfer, sales, purchase, credit-note and debit-note workflows, including recurring, reversing, optional, post-dated and cancelled entries.
- Configurable voucher types, numbering schemes and series, references, attachments, narration, approval, editing, reversal and cancellation.
- Multi-line entries, allocations, account reconciliation, error correction, exception handling and complete audit trails.
- Cost centres and categories, cost allocation, job and project costing, budgets, scenarios, projections, variance analysis and cash-flow planning.
- Account and transaction-level controls, configurable entry validation, correction workflows and period-wise comparisons.
- Multiple currencies, exchange rates, foreign-currency transactions, revaluation and exchange gain or loss.

### Sales, purchasing and invoicing

- Customer and supplier masters, delivery and billing addresses, contacts, terms, tax registrations, credit limits and price arrangements.
- Quotations, sales and purchase orders, order fulfilment, partial fulfilment, pre-closure and order tracking.
- Sales and purchase invoices for goods and services, accounting-only invoices, discounts, charges, freight, rounding and configurable document layouts.
- Delivery and receipt notes, tracking references, returns, rejection notes, credit and debit notes, and links between orders, deliveries and invoices.
- Invoice printing, previews, PDF and other exports, sharing, attachments, branding, templates and configurable fields.
- Point-of-sale workflows, price lists, multiple price levels, customer-specific pricing and promotions.

### Receivables, payables and banking

- Bill-by-bill receivables and payables, outstanding balances, part payments, advances, credit notes, multi-invoice allocations and settlement reversal.
- Ageing, overdue analysis, payment terms, credit control, interest calculations, statements and reminders.
- Bank and cash books, deposits, withdrawals, transfers, cheque management and cheque printing.
- Bank statement import, automated and manual reconciliation, matching rules, exceptions, bank charges and reconciliation reports.
- Payment instruments and integrations with supported payment and banking services, subject to provider availability.

### Inventory and manufacturing

- Stock groups, categories, items, services, units of measure, alternate units, unit conversions, barcodes and item descriptions.
- Multiple warehouses and locations, stock transfers, inward and outward movements, adjustments, physical stock counts and reconciliation.
- Batch, lot, serial number, expiry and manufacturing-date tracking where applicable; inventory allocation and traceability.
- Opening stock, stock valuation methods, cost tracking, additional purchase costs, cost of goods, gross profit and integrated accounting.
- Reorder levels, reorder quantities, location and batch ageing, item-level inventory policies, availability and demand analysis.
- Bills of materials, production, consumption, by-products, manufacturing journals, job work, material in/out and job costing.
- Allocation across multiple locations, batches and documents.
- Inventory-only and accounting-linked transactions, separate inventory and accounting finalisation, and complete stock history.

### Taxation and statutory workflows

- Configurable company and party registrations, effective dates, tax classifications, rates, exemptions and jurisdiction-specific rules.
- Indian GST support including HSN/SAC, taxable values, rates, input/output tax, adjustments, returns, reconciliation and multiple registrations.
- Electronic invoices, electronic waybills and related portal workflows where applicable and supported.
- Tax deducted and collected at source, withholding, related certificates, returns and reconciliation.
- Payroll-related statutory deductions and employer obligations, including applicable provident fund, insurance and professional-tax workflows.
- Historical and regional indirect-tax workflows where relevant, plus jurisdiction-specific compliance for supported regions, including the Gulf region, Kenya and Nepal.
- Rule updates, auditability and validation against current official requirements for each supported jurisdiction. No statutory compliance is claimed until separately implemented and verified.

### Payroll and workforce

- Employee masters, employee groups, departments, designations, attendance, shifts, leave and production-based attendance.
- Salary structures, pay heads, earnings, deductions, reimbursements, loans, advances and payroll processing.
- Payslips, payroll registers, salary payments, employer contributions, statutory records and payroll reporting.

### Reports, analysis and verification

- Detailed trial balance, balance sheet, profit and loss, cash flow, fund flow, ratio analysis and configurable financial statements.
- Day books, journals, cash and bank books, account registers, ledger statements, voucher registers and exception reports.
- Sales, purchase, invoice, order, profitability, receivables, payables, ageing and collection reports.
- Stock summary, movement, valuation, ageing, warehouse, batch, reorder, production and cost reports.
- Tax, payroll, audit, budget, cost-centre and management reports, with date ranges, drill-down, comparison, filtering and saved views.
- Custom report layouts, printing and export; verification, anomaly detection and reconciliation tools.
- Comparative and period-wise reporting, detailed and condensed views, configurable columns and drill-through from summaries to underlying entries.

### Data migration, exchange and integrations

- Guided, repeatable migration of companies, masters, opening balances, transactions, inventory, invoices, allocations, tax, payroll and historical records.
- Preservation of source identifiers, numbering, relationships, audit data, unsupported fields and migration diagnostics; duplicate detection and resumable imports.
- Pre-import previews, validation, explicit mappings, transactional application, post-import reconciliation and side-by-side report comparison.
- XML, JSON, CSV and spreadsheet import/export where appropriate, including documented interchange formats and configurable field mappings.
- Programmatic APIs and supported database or data-exchange interfaces; integrations with other business applications without silently changing existing data.

### Security, reliability and administration

- Multiple users, roles, permissions, approval flows, activity monitoring and configurable access to companies and reports.
- Complete, tamper-evident edit and activity logs for all relevant records, with attributable actions and retention controls.
- Local and network deployment, concurrent access, locking, conflict handling, recovery, data integrity checks and scalable performance.
- Verified backups, restore, disaster recovery, data repair, encryption and secure credential handling.
- Remote access, synchronisation and branch connectivity with appropriate authentication, authorisation and conflict handling.

### Experience, extensibility and delivery

- Fast keyboard-first workflows, shortcuts, accessible navigation, search, context help, guided setup and consistent error handling.
- Localisation, multilingual entry and reports, configurable dates, numbers, currencies and units.
- Custom fields, forms, reports, document templates, automation and a documented extension system.
- Configurable printing and sharing preferences, reusable document layouts, data-entry defaults and user-specific display settings.
- Stable Windows releases, installation and updates; portable core and support for additional desktop platforms where validated.
- Automated and manual verification, representative migration fixtures, performance testing, documentation and a clear compatibility matrix.
